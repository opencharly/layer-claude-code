# 2026.270.0831 — fix: stage the claude-code installer outside /tmp (batch member, distro-cachyos#95)

## Summary

Stage the Claude Code installer under the build user's home instead of `/tmp`,
so the candy no longer depends on `/tmp` being world-writable (1777) at image
build time.

| file | change |
|---|---|
| `charly.yml` (`claude-code` candy) | staging target `/tmp/claude-code-install.sh` → `"${HOME}/.claude-code-install.sh"`; the install step resolves the same value with `"${HOME}/.claude-code-install.sh"` (one mechanism, R3 — no second `getent` lookup); `version:` bumped `2026.200.1654` → `2026.270.0813` (content changed). |

Diffstat: `charly.yml | 10 +++++-----` (5 insertions, 5 deletions); head

### Root cause (R1 RCA — 8 steps)

1. **Expected.** `charly box build charly-selftest` builds the image; the
   `claude-code` candy downloads `https://claude.ai/install.sh` and installs the
   native binary.
2. **Actual.** The build aborts in the candy's download step:
   `cp: cannot create regular file '/tmp/claude-code-install.sh': Permission denied`.
   Reproduced live (below).
3. **Mechanism.** `EmitDownload` attaches a BuildKit cache mount
   `--mount=type=cache,id=charly-tmp-downloads-uid1000,dst=/tmp/downloads,...`
   to every `download:` step, then runs
   `mkdir -p $(dirname <to>) && cp -f "$__c" <to>` as `${USER}` (uid 1000).
   Separately, `EmitCmd` attaches `dst=/tmp/npm-cache` to every non-root
   `command:` step. `layer-container-nesting`'s pre-pull is a non-root
   `command:` step running `podman pull` — a **cache mount rooted under `/tmp`
   plus a nested container runtime writing under `/tmp`** — which makes BuildKit
   materialise the image's `/tmp` as `root:root 0755` instead of the base
   layer's `1777` (RCA 2026-09-24, proven by a controlled 2×2 in
   `distro-cachyos`'s `CHANGELOG/2026.268.2305.md` and in `opencharly/sdk#279`).
   The later uid-1000 `cp ... /tmp/claude-code-install.sh` then EACCESes.
4. **Missed control.** Nothing asserted the image `/tmp` mode, and the candidate
   candy assumed a writable `/tmp` at build time.
5. **Blast radius.** Any candy whose `download: to:` lands in `/tmp` is a victim
   once `layer-container-nesting` runs first. Real command + output:

   ```
   $ grep -rn --include=charly.yml -E "to:[[:space:]]*\"?/tmp/" layer-*/charly.yml \
       distro-cachyos/candy/cuda-smoke/charly.yml charly/box/cachyos/candy/cuda-smoke/charly.yml
   layer-claude-code/charly.yml:49:              to: /tmp/claude-code-install.sh
   layer-devops-tools/charly.yml:36:              to: /tmp/awscli
   layer-devops-tools/charly.yml:64:              to: /tmp/install-opentofu.sh
   layer-gst-wayland-display/charly.yml:47:              to: /tmp/gwd-src
   distro-cachyos/candy/cuda-smoke/charly.yml:21:              to: /tmp/cuda_smoke.cu
   charly/box/cachyos/candy/cuda-smoke/charly.yml:21:              to: /tmp/cuda_smoke.cu
   ```

   The systemic trigger is the emitter, not this candy.
6. **Root cause.** Two layers: **(a) ROOT** — the emitter roots BuildKit caches
   under `/tmp`, which corrupts the image's `/tmp` (**opencharly/sdk#279**);
   **(b) same class** — this candy stages a build artifact into shared `/tmp`,
   which only works while `/tmp` is healthy.
7. **Root fix.** (a) is the SDK emitter (opencharly/sdk#279); (b) is this change
   — stage into the user-owned `${HOME}`, which cannot be shadowed by the SDK
   cache placement.
8. **Documentation.** `distro-cachyos`'s `CHANGELOG/2026.268.2305.md` already
   names the `layer-claude-code` staging fix as a batch member; no stale claim to
   sweep here (the candy's `description:`/skill never mention `/tmp`).

### Coordination (R3 — not duplicated)

- **`opencharly/sdk#279`** (`fix/emitter-off-tmp`) is the ROOT fix — the emitter's
  `EmitDownload`/`EmitCmd` caches move to `/var/cache/charly/...`. It is an OPEN
  PR owned by another session; this change does **not** touch the SDK and does
  **not** duplicate it. Both are members of the named batch cutover
  **`opencharly/distro-cachyos#95`** ("/tmp build-cache cutover — retire the
  tmp-sticky belt once the SDK emitter is repinned"), member #2.
- This PR is that unclaimed member #2. The batch's other members stay in their
  owning repos: sdk#279 (member #1, root) and `box/charly-selftest` composing
  `tmp-sticky` (member #3, distro-cachyos). This change makes the `claude-code`
  build step independent of `/tmp`'s mode; sdk#279 remains load-bearing for every
  other `/tmp` writer.
